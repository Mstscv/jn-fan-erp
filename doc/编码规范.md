## 二、Java 编码规范

### 2.1 命名规范

| 类型 | 规范 | 示例 | 说明 |
|------|------|------|------|
| 项目 | `kebab-case` | `jn-fan-erp` | 全小写、横线连接 |
| 包名 | `全小写` | `com.jn.erp.material` | 域倒序+项目缩写 |
| 类名 | `PascalCase` | `SysUserService` | 首字母大写驼峰 |
| 接口 | `I+PascalCase` | `ISysUserService` | 接口以 I 开头 |
| 方法 | `camelCase` | `findByUserId` | 首字母小写驼峰 |
| 变量 | `camelCase` | `userName` | 首字母小写 |
| 常量 | `UPPER_SNAKE` | `LOGIN_SUCCESS` | 全大写+下划线 |
| POJO类 | `PascalCase` | `SysUser.java` | 对应数据库表名 |

### 2.2 分层规范

| 层 | 包名 | 职责 | 不允许 |
|----|------|------|--------|
| Controller | `controller` | 接收请求、参数校验、返回结果 | 业务逻辑、直接访问DB |
| Service | `service` | 业务逻辑编排 | 操作HttpRequest/Response |
| ServiceImpl | `service.impl` | 业务逻辑实现 | 直接暴露给Controller |
| Mapper | `mapper` | 数据库CRUD | 业务逻辑 |
| Domain | `domain` | 数据库实体映射 | 继承BaseEntity |
| DTO | `model.dto` | 数据传输对象 | 业务逻辑 |
| VO | `model.vo` | 视图对象 | 业务逻辑 |
| Config | `config` | 配置类 | @Configuration |
| Util | `utils` | 工具类 | 静态方法 |
| Constant | `constant` | 常量定义 | final class |

### 2.3 Controller 规范

```java
@RestController
@RequestMapping("/system/user")
public class SysUserController extends BaseController {
    
    @GetMapping("/list")
    public TableDataInfo list(SysUser user) { /* 分页查询 */ }
    
    @GetMapping("/{userId}")
    public AjaxResult getInfo(@PathVariable Long userId) { /* 详情 */ }
    
    @PostMapping
    public AjaxResult add(@Validated @RequestBody SysUser user) { /* 新增 */ }
    
    @PutMapping
    public AjaxResult edit(@Validated @RequestBody SysUser user) { /* 修改 */ }
    
    @DeleteMapping("/{userIds}")
    public AjaxResult remove(@PathVariable Long[] userIds) { /* 删除 */ }
}
```

### 2.4 Service 规范

```java
public interface ISysUserService {
    SysUser selectUserByUserName(String userName);
    List<SysUser> selectUserList(SysUser user);
    int insertUser(SysUser user);
    int updateUser(SysUser user);
    int deleteUserByIds(Long[] userIds);
}
```

### 2.5 异常处理

- 业务异常: 抛 `ServiceException`
- 参数校验: `@Validated` + `@NotBlank/@NotNull`
- 全局异常: 由 `GlobalExceptionHandler` 统一处理
- 禁止在 Controller 中 try-catch 后吞掉异常

### 2.6 日志规范

```java
// 使用 Lombok @Slf4j
@Slf4j
public class SysUserServiceImpl {
    public void someMethod() {
        log.info("用户 {} 执行了操作: {}", userId, operation);
        log.error("操作失败: ", exception);  // 异常传参用 , 不要用 +
    }
}
```

### 2.7 SQL 规范

```sql
-- 关键字大写
SELECT u.user_id, u.user_name FROM sys_user u WHERE u.del_flag = '0'

-- 多表关联使用表别名
SELECT u.*, d.dept_name FROM sys_user u 
  LEFT JOIN sys_dept d ON u.dept_id = d.dept_id

-- 避免 SELECT *
SELECT u.user_id, u.user_name  -- 明确列名

-- 逻辑删除统一字段 del_flag
WHERE del_flag = '0'
```

## 四、Git 提交规范

### 4.1 提交格式

```
<type>(<scope>): <subject>

<body>
```

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复Bug |
| docs | 文档 |
| style | 代码格式 |
| refactor | 重构 |
| test | 测试 |
| chore | 构建/CI |

### 4.2 示例

```
feat(material): 新增物料主数据管理模块

- 物料CRUD(含风机属性扩展)
- Excel批量导入
- 物料编码自动生成
```

```
fix(inventory): 修复库存扣减时并发问题

- 添加乐观锁version字段
- 库存变更使用原子操作
```

## 五、数据库变更管理

### 5.1 变更流程

1. 创建版本化 DDL 文件: `V20260526__create_jn_material.sql`
2. 提交到 Git 仓库
3. 部署时通过 Flyway/Liquibase 自动执行

### 5.2 DDL 规范

```sql
-- 头部注释
-- 精恩风机ERP - V2.0.0
-- 日期: 2026-05-26
-- 说明: 创建物料主数据表

ALTER TABLE 必须使用 ALTER TABLE ... ADD/DROP/MODIFY
DROP TABLE 必须有 DROP TABLE IF EXISTS
```

## 六、代码审查 Checklist

- [ ] 命名符合规范（不缩写/不拼音/不中英混）
- [ ] 无硬编码（用常量/枚举/字典配置替代）
- [ ] 异常处理正确（不吞异常/不打印堆栈到前端）
- [ ] SQL 无 N+1 问题
- [ ] 循环中不调用数据库
- [ ] 关键逻辑有日志
- [ ] 敏感数据不暴露（密码/Token）
- [ ] 接口返回统一格式（AjaxResult/R）
- [ ] 没有 TODO 未处理
- [ ] 提交信息符合规范
